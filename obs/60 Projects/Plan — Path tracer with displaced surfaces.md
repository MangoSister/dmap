# Plan — Path tracer with displaced surfaces

Implementation plan for master plan §7 Phase 2 item 2 (the ray query at parity) and for the engine integration deferred at the end of the A-MVP: a CPU path tracer in `code/cpp` that intersects tessellation-free displaced surfaces through the eight-channel pyramid, treats emissive displaced surfaces as lights through the A-MVP samplers, and mixes any number of displaced objects with ordinary meshes in one scene described by a toml config. Like the other plan notes, this note is stateless and edited in place; reasoning and history go to [[Log — Conservative metric queries]] (entries of 2026-09-06).

## Goal

Three deliverables, in dependency order:

1. **A ray intersector on the pyramid.** TFDM's texture-space traversal at full resolution, reading the stored min-max channel for the box test and the Taylor channels for a second, tilted bound. In box mode it is TFDM, so parity holds by construction. In the other modes it may prune more. TFDM's level-of-detail scheme is not considered; the hierarchy serves pruning only, and every comparison with TFDM is at full resolution. The traversal cost measurement that the master plan has called the gating experiment since 2026-08-30 is T5 of this plan.
2. **Displaced surfaces as lights.** The five A-MVP samplers (emission table, product table, area descent, product descent, receiver-aware descent) over multi-triangle emitters, selectable per object, any number of them in a scene, with MIS against BSDF sampling.
3. **A path tracer and a scene format** that mix any number of displaced objects and ordinary meshes, with any ks BSDF on a displaced surface, assets from OBJ and glTF, and displacement attached either by a toml overlay or by glTF extras exported from Blender. The tracer is ks's `SmallPT`, extended; every scene without displacement must render exactly as before.

## Ground rules

- dmap-specific code lives in `code/cpp/src`. The interface generalizations of T7 are the one deliberate exception: they are engine changes inside the ks submodule (the user's own renderer, `keepsake`), kept minimal, and committed to that repository separately.
- **Every task is scene-driven.** The validation and study tasks take their scene from the shared scene specification of T2, never from hard-coded assets, and construct their oracles (pre-tessellated substitutes, converged references) from that same specification. Adding a scene later means adding a `[[task]]` block or a config file, not code. The initial scene set is listed under T2.
- Each phase ends with a task registered in `main.cpp`, driven by a config in `code/data/configs`, that answers one question and prints its verdict. Every task is seeded. Run clang-format on every touched C++ file.

## What the investigation found

Summary; the reasoning is in the log.

- **TFDM's algorithm as GfxExp implements it** (`code/third-party/GfxExp/tfdm`, CUDA and OptiX). Per base triangle, an object-space AABB from the min-max mipmap over the triangle's texel footprint is the acceleration-structure primitive. The intersection program walks the implicit quadtree over the triangle's uv bounding box without a stack: up to four roots, `down`, `next`, and `up` with the child order sorted by the ray direction, a triangle-versus-square test that discards texels outside the triangle, and per node an AABB in a per-triangle uv-aligned tangent space. That AABB comes from affine arithmetic over three symbols (u, v, h), with the interpolated normal normalized through a Min-Range approximation of 1/√x. The AABB is tested against the ray with the current maximum distance; a hit either descends or, at the finest level, runs one of three leaf intersectors: the box itself, two triangles per texel, or Newton iteration on the true surface P + hN. The statistics are node tests and leaf tests per ray. The paper's ablation says texel discard is the biggest win and traversal, not leaf intersection, dominates cost.
- **What our pyramid changes.** Nothing at coarse levels. h_min and h_max are exactly TFDM's min-max mipmap at full resolution: both are the min and max over texel corners, folded by min and max. The new information is (h0, gu, gv, r): over the cell, the surface lies within r of a tilted plane, and the channel study measured that region thinner than the box below 8-texel cells. An AABB extracted from it is not thinner, because collapsing the tilt back to an axis-aligned extent costs |gu| s + |gv| s, which is the loose recovered interval of the study. The slab has to be tested as a tilted region. That test is a linear inequality along the ray, not a box test (D3).
- **ks** (`code/cpp/src/ks`). `Scene` is embree over subscenes of `Geometry` objects, instanced with transforms. `Geometry` is an abstract base with `create_rtc_geom` and `compute_intersection`, so a new geometry type needs no change to ks. Lights are `Light` objects (sky, directional, point, mesh triangle) behind an abstract `LightSampler`. Mesh lights are built by `Scene::build_mesh_lights` from `MeshGeometry` only, and the BSDF-hit MIS path looks a light up by (instance, geometry, primitive) and receives the concrete `MeshTriLight` type. `Light::sample` takes the shading point and one 2D random number, with no shading normal and no sampler. `SmallPT::trace` is one hundred lines: intersect, add emission with MIS through the mesh-light lookup, `Material::sample_with_nee` (which runs ks's next-event estimation and the BSDF sample together), Russian roulette. Mesh lights are referenced only in `light.{h,cpp}`, `scene.{h,cpp}`, and `small_pt.cpp`; the GPU code does not touch them. The config system registers asset parsers by table prefix (`[texture.x]`, `[material.x]`, `[mesh_asset.x]`, `[compound_mesh_asset.x]`) and tasks by `[[task]]` type, so a new asset type is one registered parser. The glTF loader builds PrincipledBSDF materials with emission (including `KHR_materials_emissive_strength` and texture transforms) and a scene graph of instances, ignores `extras`, and exposes `traverse_gltf_scene_graph` publicly.
- **dmap today.** One base triangle with the identity chart (barycentric coordinates are the texture coordinates, the whole tile per triangle), amplitude in mean-edge units, a `DescentSampler` that owns its own pyramid and a per-triangle clipped emission-sum pyramid, `DisplacedEmitterLight` mirroring the ks light contract standalone, and `render_displaced_emitter`, a two-object direct-lighting renderer. Everything that touches the parameterization assumes the identity chart. Of the test assets, `cc_torus.obj`, `cc_oracle.obj`, and `spot.obj` carry texture coordinates; `armadillo.obj` and `stanford-bunny.obj` do not.

## Design decisions

- **D1. The intersector is an embree user geometry in dmap.** `DisplacedGeometry : ks::Geometry`, one user primitive per base triangle, an object-space AABB per primitive from the min-max channel (the port of TFDM's per-triangle AABB pass), intersect and occluded callbacks that run the traversal and call `rtcFilterIntersection` and `rtcFilterOcclusion`, so ks's context filters (opacity maps, the local-geometry filter) keep working. Embree hands the callback the ray in instance space, so instancing and mixed scenes come for free: a subscene holds `MeshGeometry` and `DisplacedGeometry` objects side by side, and a scene holds any number of either.
- **D2. The traversal is TFDM's at full resolution, ported to double on the CPU, with the node test selectable.** Roots, `down`, `next`, `up`, the direction-sorted child order, texel discard, the per-triangle tangent space, the affine forms for uv, h, and the normalized interpolated normal, all as in GfxExp. Then `bound = "box"` is TFDM by construction and its node-test counts are TFDM's counts. Modes: `box`, `slab`, `both` (the intersection of the two t-intervals), and a level policy `slab_max_level` that reads the slab only at levels up to k. The default is k = 1, the leaves and 2-texel cells, settled by T5 ([[Result — Traversal cost study]]): the slab at the leaves cuts the leaf tests by 10 to 40% for no extra node test, one level up saves 1 to 5% of the node tests, and deeper levels save less than their slab evaluations cost. Leaf: Newton on the true surface by default, certified. GfxExp's bilinear mode runs one Newton iteration from the texel centre, which on rough content returns the far root or nothing for about one ray in a hundred (log 2026-09-07); here the texel is searched as a quadtree with the traversal's own affine bounds (P affine, the bilinear h affine plus a twist remainder, the texel's normalized normal restricted to each sub-square), sub-squares whose bounds exclude the ray are dropped, the rest are visited nearest first and pruned by the best root, and Newton runs from the centres of the finest survivors (five subdivisions), so a root can be missed only when two crossings share one finest sub-square. The two-triangle leaf is the validation oracle (D4) and the exact intersector of the texel-aligned mesh. No level of detail: traversal always descends to the texel level, and the hierarchy is used for pruning only.
- **D3. The slab test is a linear inequality along the ray in the tangent space.** In the tangent space the base point is (u, v, 0), the interpolated normal is n = (n_x, n_y, n_z) as affine forms over the cell (TFDM's forms), and a surface point is (u + h n_x, v + h n_y, h n_z) with h = h0 + gu (u − u0) + gv (v − v0) + ρ and |ρ| ≤ r. Eliminating u, v, and ρ gives

  $$z\,(1 + g_u n_x + g_v n_y) \;-\; n_z\,\big[h_0 + g_u (x - u_0) + g_v (y - v_0)\big] \;=\; n_z\,\rho \;\in\; [-n_z r,\; n_z r].$$

  With n ranging over its interval hull this is one linear form in (x, y, z) with interval coefficients. Along the ray it is an affine function of t with interval coefficients, and the admissible t set is the interval where that interval-valued function meets [−n_z r, n_z r], a few operations. When n is constant it is exactly two planes tilted by (gu, gv) and separated by 2r, the slab of [[Taylor-model bound pyramid]] §6. As n varies it widens by the normal's variation and stays conservative, since dropping the correlation between the coefficients only enlarges the set. The box t-interval comes from the same affine forms as TFDM's AABB, and `both` intersects the two, with a rounding tolerance of 10⁻⁹ relative on the ends: over a perfectly flat cell both intervals degenerate to the one crossing of a plane, rounded differently, and without the tolerance the intersection is empty and the hit is lost (found by S6's panelled map on 2026-09-07, 14% of its surface points; the rock and cobble maps of S1 to S3 have too few exactly flat cells to show it). This is where the traversal can beat TFDM. D2 makes sure it cannot lose at coarse levels, where the box alone is read.
- **D4. Oracles.** With the identity chart and the pre-tessellated barycentric grid at n_tess equal to the texels per side, the two-triangle leaf describes exactly that mesh (same nodes, with the diagonal chosen to match `tessellation_grid`). So embree over the pre-tessellated mesh is an exact oracle for the whole traversal in that mode. The Newton leaf is checked by its residual, by never-miss on sampled surface points, and against a finer mesh within that mesh's chord error. For general charts the finer mesh is texel-aligned (`append_texel_tessellation`): every texel meeting the domain is split into m × m sub-cells, each split along the same diagonal, and clipped where it straddles the domain. The barycentric grid does not serve here: its micro-faces cross the creases of the bilinear height at texel boundaries and round them, so a ray through a crease can hit the true surface and miss the mesh by more than any chord estimate. With m = 1 the texel-aligned mesh is the two-triangle leaf's own surface, which is what T5 compares against. Every oracle mesh is generated from the scene specification, never stored.
- **D5. General chart, shared tile data, and where clipping is exact.** Per-vertex texture coordinates. Build the base triangle directly in texture parameterization (edges [e1 e2] J, normal derivatives [Mu Mv] J, with the object's `uv_scale` and `uv_offset` folded into J), so every pointwise formula, the propagation, and the samplers run unchanged, and the parameter-to-area factor is √det G in those coordinates. Bound tightness under general charts is measured ([[Result — Chart dependence study]]): the metric quantities are chart-indifferent, the normal cone loosens 19% under shear, and the frame fix for it is a numpy propagation item outside this plan. Tiling wraps texel indices per level. The pyramid is per displacement asset and shared by every triangle of every object that uses it; a sampler holds a pointer, not a copy. The emission statistics (a mean pyramid and a max pyramid over unclipped cells) belong to the object whose material emits, not to the asset: emission is a material property in the object's own texture coordinates and is not periodic over the tile, so they are built over an aligned power-of-two box of the tile's leaf lattice that covers the object's domain, zero outside, at the displacement's leaf resolution (T2). The experiments' emission over the tile is the repeating special case of the same structure. The triangle's shape in the tile enters at query time in three places, and only one needs an exact area. (1) Admissibility of a child is a boolean: the overlap class and, for the product variants, mass > 0; a cell classified fully inside uses its full area and the tile's sums. (2) The weight of a straddling cell uses its exact clipped area or emission mass. (3) The leaf density divides by the exact area of leaf ∩ triangle. All three read the triangle's footprint, built once at construction: the 2 × 2 root block from TFDM's root rule and a tree of the straddling cells below it, each child carrying the overlap class, the exact clipped area, and the exact clipped emission mass, from one clip of a square against three half-planes per straddling leaf and additive folds above. Its size is proportional to the perimeter in texels, its per-sample cost is one lookup per straddling child, and it makes the flat-patch check exact and the identity chart reproduce S7 bit for bit (log 2026-09-07; this replaced the probe-fraction estimate first recorded here). Certified-zero pruning stays exact through the max pyramid, and memory stays proportional to the tile. The identity chart is a special case and must reproduce the S6 and S7 numbers.
- **D6. Displacement in world units, per asset.** h = strength × (t − midlevel), with t the texture value in [0, 1]. This is Blender's Displace-modifier convention and replaces the amplitude × mean-edge convention of the experiments, which stay available in their own tasks. Texture texels are node values. The (2^L + 1)-th node is the wrapped first node under repeat and the duplicated last node under clamp, so a 2^L-texel texture gives 2^L leaf cells. An optional `resolution` box-downsamples for cheap experiments. Tile orientation follows ks's texture convention: texel row 0 is the top of the image, so v = 0 is the image's top edge; texture coordinates that run upward (OBJ) are flipped, v → 1 − v, before the tiling, glTF coordinates are not, exactly as ks's `TextureField` does, and `flip_v` on a `displace` entry overrides the default. The chart of a triangle is then t = (u, v') × uv_scale + uv_offset.
- **D7. The tracer is ks's `SmallPT`, extended through minimal interface changes, and every non-displaced scene must render exactly as before.** The changes, all inside ks:
  1. `Light` gains a virtual `sample(const Intersection &shade, PTRenderSampler &sampler, vec3 &wi, float &wi_dist, float &pdf)`. Its default draws `sampler.sobol.next2d()` and forwards to the existing `sample(p, u, ...)`, so every existing light consumes the same sample stream as today. Displaced lights draw the descent from `sampler.rng` and the leaf point from that 2D draw, so Sobol dimensions are unchanged for everyone.
  2. A new abstract `AreaLight : Light` with `eval(const Intersection &hit)` and `pdf_hit(const Intersection &shade, const vec3 &wi, const Intersection &hit)`, the latter defaulting to the existing `pdf(shade.p, wi, hit.thit)`. `MeshTriLight` derives from it. The receiver-aware sampler needs the shading normal and the hit's texture coordinates, which is why the pdf takes both intersections.
  3. An abstract `AreaLightShared` (instance id, geometry id, light count, light accessor, primitive-id accessor) that `MeshLightShared` implements. `Scene::mesh_lights` becomes `area_lights`, and `Scene::build_mesh_lights` becomes `build_area_lights`, which asks each geometry through a new virtual `Geometry::create_area_light(inst_id, geom_id, transform, material)`; `MeshGeometry` returns a `MeshLightShared` when the material emits, other geometries return null by default. `Material::emission` non-null stays the trigger.
  4. `LightSampler::get_mesh_light` becomes `get_area_light(MeshTriIndex)`, returning the abstract `AreaLight`; `PowerLightSampler` is built over `AreaLightShared`.
  5. `next_event_estimate` calls the new `sample(hit, sampler, ...)`.
  6. `SmallPT::trace` keeps the previous vertex's `Intersection` across bounces and uses `get_area_light`, `eval`, and `pdf_hit` in the emission-hit branch. Nothing else in the loop changes.
  7. A bug fix found by T8's MIS check, not an interface change: `next_event_estimate` weighted the light strategy by the light's pdf alone while the BSDF-hit branch weighted it by the pdf times the light selection probability, so the two weights did not sum to one and every scene with more than one light (every mesh light with more than one triangle) rendered direct lighting too bright, by 2% on S6. The weight now carries the selection probability on both sides. This is the one intended change of an existing image; the regression golden was re-rendered after it.
  8. Robustness, no image change: `compute_mesh_light_importance` asserted on a triangle much smaller than an emission texel whose texture box wraps to an empty box; such a box now contributes nothing. Hit by S7's 2-million-triangle substitute mesh light.
  9. A second bug fix found by T8's substitute check: the importance table of a textured mesh light was filled at texel centres passed through the field's own uv transform (flip, scale, offset) while the per-triangle queries were made in texture space, so with a flipped or tiled emission texture the table was mirrored or scaled against the mesh and most emitting triangles were dropped from the light list (S6's substitute rendered 4.8× too dark). The texel centre is now mapped back through the transform first. Constant emission (the regression scene) takes the other path and is unchanged.

  The `small_pt` task stays as it is and keeps driving non-displaced scenes. dmap's `path_trace` task (T8) builds the scene with displacement and calls `SmallPT::run` with a `SmallPTInput`; the tracer is shared, not copied. Subsurface materials keep working on meshes through `Material::sample_with_nee`; on displaced surfaces they are not supported in the first version. The regression gate is bit-identity: before any ks file is touched, T7 renders a fixed regression scene with the unchanged binary and stores the images; afterwards `small_pt` must reproduce them bit for bit, and so must `path_trace` with no `displace` entries.
- **D8. Scene specification.** Two asset types and one scene table, all read by `scene_spec`. `[displacement.<name>]` (`map`, `strength`, `midlevel`, `wrap`, `resolution`, `pyramid_build`) builds the tile data once; every object naming it shares them. `[scene.<name>]` is itself a registered asset, loaded after every other kind, so a task names its scene (`scene = "scene.s2"`); a scene file under `code/data/scenes/` holds its own assets (scene-prefixed keys) and its scene table, and a task config prepends scene files with `include = [...]`, which `main.cpp` concatenates before parsing. The scene table takes ks's single-asset form (`object` or `compound_object` with ks's `material` list) or an `objects` list of placements (`asset`, optional `name`, `to_world`, `material` per shape; for a glTF object one per node with a mesh, `""` keeping the file's material). A shape is an OBJ shape or a glTF node with a mesh, named `object/shape`, and matched by that name, by the shape or node name, or by the object name when it has one shape. The `displace` list attaches an asset to a shape (`object`, `displacement`, `uv_scale` with an optional `uv_scale_v` for the v axis alone, `uv_offset`, `flip_v`, optional `material` override, `emitter_sampler`, `emission_tiled` when the material's textures tile with the displacement so the emission statistics are one repeating tile instead of a box over the domain, `emission_supersample`, per-entry `traversal` override); the scene's `traversal` table holds the defaults; `camera`, `sky` and `light` are parsed as `small_pt` parses them. Materials from toml take an `emission` field (an inline `shader_field_3` table), which dmap's material parser adds to ks's, so toml mesh lights work in `small_pt` too. glTF `extras` (`dmap_displacement`, `dmap_strength`, `dmap_midlevel`, `dmap_uv_scale`, `dmap_uv_offset`) fill the same record: `dmap_displacement` names a toml asset, whose strength and midlevel the extras must repeat if they carry them (no per-object strength, D9), or, when no toml asset of that name exists, a map file next to the glTF from which the asset is synthesized with the extras' convention. A toml entry for a shape that also carries extras replaces the extras record whole. Several assets in one scene and several objects per asset are both fine.
- **D9. Out of the first version.** Level of detail, in any form. Per-instance strength, which is analytic in the node and comes later. Watertightness across UV seams, TFDM's open problem; demo assets avoid visible seams. float32 storage. Vector displacement.

## Phases

### T1 — General chart and shared tile data

Generalize the A-MVP core from the identity chart to per-vertex texture coordinates, and make the per-tile structures shareable.

- `displaced_surface.{h,cpp}`: `BaseTriangle` gains its three texture coordinates and the affine map from texture coordinates to barycentric coordinates (with the object's tiling folded in). Pointwise fields take texture coordinates: G in texture coordinates is Jᵀ G J, the gradient converts by J⁻ᵀ, the area factor by |det J|. `HeightGrid` gains the wrap mode and the world-unit height convention (D6). `displaced_tessellation` evaluates S through the same map, so pre-tessellated oracles exist for every chart.
- New `uv_clip.{h,cpp}`: the square-versus-triangle overlap classification (TFDM's separating-axis test, shared with the traversal), the exact clip of a square against the three half-planes with its area and a uniform sample inside it, and the identity-chart closed form kept as the special case and as the test.
- `taylor_pyramid.{h,cpp}`: construction from a wrapped or clamped texture (D6) and wrapped indexing per level for tiling.
- New `emission_tile.{h,cpp}`: mean and max pyramids of a scalar emission grid over a tile (the existing `MipPyramid`, moved), with two sources: a `TextureGrid`, or a ks `ShaderField3` by supersampled luminance per texel.
- `descent_sampler.{h,cpp}` and `displaced_emitter_light.{h,cpp}`: take pointers to the shared pyramid and emission tile; the per-triangle footprint of D5 (roots and boundary tree) carries the clipped areas and masses; the descent starts with a root choice among the four roots; the leaf draw is rejection inside the leaf square with a direct polygon draw after a bounded number of rejections; the table baselines run over the domain's texel box. The sampled and re-walked pdfs are unchanged in form.
- Verify, task `validate_chart`: (1) the general constructor with identity texture coordinates reproduces the barycentric convention bit for bit, and `validate_pointwise` and `validate_descent` are re-run; (2) under random charts with a linear height field, h, the displaced position, the normal, and the eigenvalues agree with the identity-chart triangle at the mapped point, √det G agrees up to |det J|, and |Su × Sv| equals √det G; (3) on the mesh's own layouts and on random tiled charts, exact clipped areas sum to the domain area, footprint totals match an independent per-texel sum, the identity closed form equals the exact clip, and the overlap classification agrees with the exact area at every cell of every level; (4) the four S6 checks hold under a random chart and under the same chart tiled three times with an offset, as chart blocks of `validate_descent`. Done 2026-09-07, all pass; the numbers are in the log.

### T2 — Displacement asset and scene specification

The shared scene specification every later task reads. Its product is the list of displaced object descriptions (base mesh in double, one base triangle per face in tile parameterization, the shared tile data, material, sampler kind, traversal options, and the object's emission statistics when its material emits), which T3 to T5 consume without embree; the ks scene comes with T6.

- `displacement_asset.{h,cpp}`: the `[displacement.<name>]` asset (D6, D8): the closed node grid, the height-grid view, and the pyramid, built once and shared.
- `scene_spec.{h,cpp}`: the scene table (D8), from a `[scene.<name>]` asset or a task table: objects and shapes, the two displacement sources merged per shape, name resolution, the chart per triangle with the v flip and the tiling folded in, the clamp-mode domain check, degenerate texture triangles reported, the emission box for emissive materials, camera and lights, and `tessellated(object, n)`, the pre-tessellated substitute with texture coordinates mapped back to the object's own.
- `gltf_asset.{h,cpp}`: ks's compound mesh asset plus the file path, the node names and the `dmap_*` extras, registered under ks's `compound_mesh_asset` prefix. `emissive_material.{h,cpp}`: ks's material parser plus `emission`. `traversal_options.{h,cpp}`: D2's options with per-entry override. `main.cpp`: `include`, the registrations, `describe_scene`.
- Scene set under `code/data/scenes/`, one file each with its own assets: (S1) `s1_triangle`, the experiment triangle (`scenes/assets/s7_triangle.obj`, written by `code/python/tools/make_scene_assets.py`) with the identity chart, rock at 64 texels, strength 0.2 × mean edge, no flip, clamp, emissive; (S2) `s2_torus_rock`, cc_torus with its own layout, rock at 256 texels, a principled BSDF; (S3) `s3_spot_cobble`, spot with cobble tiled four times; (S4) `s4_mixed`, a floor, two placements of the torus sharing one rock asset (one with a `box` override), a displaced emissive plane, a plain mesh light, the environment map as the sky; (S5) `s5_blender`, a headless Blender export (`code/python/tools/blender_s5.py`) whose nodes carry the extras, with a toml overlay repeating two of them and one node naming a map file; (S6) `s6_scifi` (added in T8), two placements of a panel displaced with the sci-fi map set of `code/data/simple/scifi` (a 2048-texel EXR height field used at 512 texels, an albedo map, an emission map of thin strips and small patches over 5% of the panel, scaled by 40), a diffuse floor and torus, no other light; (S7) `s7_orbit` (added in T8), the sci-fi station: `scifi_orbit_bunny.glb`, a bunny inside a torus, the torus displaced and textured with the sci-fi maps tiled 16 times along the ring and 4 around the tube (`uv_scale_v`, square tiles of 0.78 units), its emission repeating with the tile (`emission_tiled`), a brushed-metal bunny from the scene's material list, a weak directional sun, no sky; `s7_64` is the same at 64 texels per tile for the pre-tessellated reference. More are added as files.
- Verify, task `describe_scene` (`configs/describe_scene.toml` includes the five scenes): (1) no errors and every entry resolved to one shape; (2) pointer equality of the tile data across objects sharing an asset; (3) with `check_extras`, the extras record equals the overlay record per shape; (4) with `reference_n_tess`, the substitutes build and their area converges to the metric area as the subdivision doubles. Done 2026-09-07, all five pass; the numbers are in the log.

### T3 — Node bounds in space

The per-node tests of D2 and D3 as a standalone unit, on one base triangle in its tangent space.

- `affine_form.{h,cpp}`: affine forms over the two cell symbols εu, εv with every other error symbol aggregated into one remainder, GfxExp's `AAFloatOn2D` in double: sum, product, scalar product, interval extraction, the conservative squared length and the Min-Range 1/√x, and vectors of forms under a linear map. The remainder is where the height (mid ± half-range) and the nonlinear parts enter; it plays the third symbol's part, and keeping the arithmetic GfxExp's is what makes the box TFDM's box.
- `node_bounds.{h,cpp}`: the tangent frame ([e1 e2 ng]⁻¹ about q0, so P(s, t) ↦ (s, t, 0) and ng ↦ (0, 0, 1)); `node_bound` (the cell clipped to the triangle's texture bounding box, the normalized normal's image m as an affine vector, TFDM's AABB); `slab_form` and `slab_interval` (D3's linear form with interval coefficients, anchored at the entry of the cell's column and clipped to it, since the slab is unbounded sideways and the coefficient widths grow with the distance from the anchor); `box_interval`, `both_interval`, `node_interval` with D2's level policy; `triangle_height_range` (TFDM's footprint walk over the min-max channel) and `triangle_aabb` (three parallelograms, affine arithmetic in object space). Rays keep the object-space parameter, so intervals are in object units.
- Verify, task `validate_node_bounds`, over the displaced objects of a scene (sampled triangles), for every cell of every level from the footprint's roots to the leaves: (1) dense surface samples satisfy the box, the slab with interval coefficients, the exact slab identity F = m_z ρ with |ρ| ≤ r, and the triangle's object-space AABB, 0 violations; (2) for random rays through those samples, the box, slab and both intervals contain the sample's t, 0 violations; (3) the tightness table per level with the median interval length of box, slab and both in object units, and the crossover level, the coarsest level at and below which the slab is the shorter interval. Verdict: conservative, and the crossover reported. Done 2026-09-07 on S1, S2 and S3, all conservative; the tables and the reading of the crossover, level 2 on S1 against the channel study's level 3, are in [[Result — Node bound tightness]]. - Verdict, three falsifiable parts: (1) `both` never tests more nodes than `box`, at every level; (2) the level at which the slab starts to prune more than the box matches T3's crossover; (3) the reported policy minimizes time per ray, and the ratio to the pre-tessellated mesh is recorded whatever it is. ## Next direction, outside this plan (recorded 2026-09-08)

- **Object-level light sampler.** T8's arrangement enumerates every emitting base triangle at scene build (its footprint or table, its emission mass, one ks light each) and leaves the selection among them to ks's power table, which ignores the receiver. T9 measured the consequence on S7: 4,416 lights, 172 MB of footprints, and every sampler kind within 25% of each other under MIS because the selection above them decides the variance ([[Result — Emitter sampling in scenes]]). The premise of a tessellation-free emitter is that the emitting set is never enumerated ahead of time and that the sampler belongs to the object, or to the tile when the map repeats, not to the triangle. The direction. One ks light per (instance, displaced object) instead of one per emitting base triangle, with a single hierarchical descent over the object's texture domain. Above the tile level the nodes are cells of the object's uv box (for the station ring, 16 × 4 tiles), each carrying what a light BVH cluster carries: a spatial bound from the base triangles' boxes and the height range, a normal cone from the vertex normals and the height range, the emission mass, and a precomputed metric-weighted mass summed over the base triangles it covers, so that only the receiver term is evaluated per sample; descent weights are receiver-aware from the object's root. At and below the tile level the nodes are the shared pyramid's cells, stored once per tile however many repeats, with the metric composed per copy at the leaf as now. Cells that base-triangle edges cross are stored once in the object's tree with a list of pieces (triangle, clipped area, clipped mass), instead of once per triangle per level as the footprint tree does today. Overlapping or mirrored uv charts add one discrete choice of the copy with a deterministic weight, so a surface point's density is pdf_uv × P(copy | uv) / √det G of that copy. The pdf of a hit walks the same tree from the object's root, as `pdf_hit` walks the triangle's tree today, so MIS is unchanged. The pyramid, the emission tile, the wrapped indexing, admissibility from clipped mass, the probability floor, the leaf draw and the pointwise metric at the leaf all stay; the midpoint composition of √det G and its moment-channel remedy are independent of this change. The per-triangle lights stay as the baseline and for the pre-tessellated substitutes. What it claims: receiver-aware selection over the whole emitter without enumerating emitting triangles ahead of time, at a per-sample cost proportional to the tree's depth, with memory that depends on the base mesh only through the uv tree and not on a per-triangle footprint or table. The measurement that would show it is S7's ladder run again with the object-level sampler in the row set: today every kind sits within 25% of each other there because the selection above them is the same. Recorded here and in master plan §5A; whether it is built is a gate decision (master plan §7).
